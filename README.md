# QQ 智能对话机器人

一个跑在自己 QQ 号上的对话机器人：通过 OneBot 11 协议接入，由大模型驱动多轮聊天，具备长期记忆、情绪与关系状态、主动搭话、联网检索、图片理解和语音回复。

**完全自研，不依赖 NoneBot / go-cqhttp 框架**——消息收发、对话编排、记忆、调度都是手写的，目的是把每一步弄清楚。

## 功能

| 模块 | 说明 |
|---|---|
| 多轮对话 | DeepSeek 驱动，回复拆成 1–4 条消息发送，模拟真人打字节奏 |
| 长期记忆 | 全部对话追加写入 `chat_log.jsonl`；每天定时把未总结的对话压缩成记忆条目，聊天时按关键词检索最近相关条目注入上下文 |
| 情绪系统 | 0–4 级，随静默时长升级、随时间衰减，回复后降级；情绪会写进 prompt 影响语气 |
| 关系状态 | 好感 0–100 分五档，影响主动搭话的频率与静默阈值 |
| 主动搭话 | 沉默超时后按概率发起，七种角度轮换（刚在干嘛 / 今天的小事 / 吐槽 / 想吃什么 …），刻意避免「吃了吗」式查岗 |
| 生活状态 | 按小时切换在干嘛（睡觉 / 上课 / 吃饭 / 追剧），随机生成一句生活小事，作息会影响回复延迟和不回概率 |
| 拟人化 | 5% 概率先发错字再撤回、30% 概率引用上一条消息、发送前显示「正在输入」 |
| 节奏控制 | 连发消息合并成一次回复（6 秒去抖）、按信息量决定回不回、安静时段不打扰 |
| 联网检索 | 模型自主调用 `web_search`（Serper / 百度 / Bing / DuckDuckGo 多源回退）和 `fetch_url`（正文提取），带 SSRF 防护 |
| 图片理解 | 收到图片交给视觉模型描述，再把描述作为上下文交给角色模型 |
| 语音回复 | edge-tts 合成，通过 OneBot `record` 段发送 |
| 表情 | 按历史使用频率加权随机补发，模型也可主动触发 |
| 稳定性 | 断线自动重连、端口级单实例锁（避免多进程抢占同一条 WebSocket）、启动后补收离线消息 |

## 架构

```
QQ 客户端
   │
   ▼
NapCat（OneBot 11 实现）
   │  WebSocket
   ▼
onebot.py ──► bot.py（消息编排）
                ├── llm.py          DeepSeek 调用
                ├── memory.py       对话记忆 / 长期记忆摘要
                ├── pacing.py       去抖、回复概率、安静时段
                ├── humanness.py    错字、引用、正在输入
                ├── idle.py         主动搭话调度
                ├── life.py         生活状态时间线
                ├── relationship.py 好感度
                ├── webtools.py     联网搜索与网页抓取
                ├── vision.py       图片理解
                ├── voice.py        语音合成
                ├── weather.py      天气
                └── reminders.py    提醒
```

## 快速开始

**1. 安装依赖**

```bash
pip install -r requirements.txt
```

**2. 配置**

复制 `.env.example` 为 `.env`，填入自己的配置：

```bash
cp .env.example .env
```

至少需要：

- `OWNER_QQ`：机器人服务的对象（你自己的 QQ 号）
- `DEEPSEEK_API_KEY`：大模型 API Key
- `ONEBOT_WS`：OneBot 的 WebSocket 地址，默认 `ws://127.0.0.1:3001`

**3. 启动 OneBot**

本项目通过 OneBot 11 协议与 QQ 通信。可以用 NapCat、Lagrange 等任意 OneBot 11 实现，在它的配置里开启正向 WebSocket 服务（默认 3001 端口），然后用机器人的 QQ 号登录。

**4. 启动机器人**

```bash
python bot.py
```

看到 WebSocket 连接成功、机器人开始响应消息即表示运行正常。

## 运行测试

测试不依赖真实 QQ，也不需要 API Key：

```bash
python tests/test_core.py
python tests/test_e2e_mock.py
```

`test_core.py` 覆盖消息切分、提醒解析、记忆存储、上下文构造等纯逻辑；`test_e2e_mock.py` 用一个模拟的 OneBot 服务端跑完整收发链路。

## 配置项

完整配置见 `.env.example`，几个关键项：

| 变量 | 默认值 | 说明 |
|---|---|---|
| `OWNER_QQ` | 必填 | 机器人主要服务的 QQ 号 |
| `DEEPSEEK_API_KEY` | 必填 | 大模型 API Key |
| `LLM_MODEL` | `deepseek-chat` | 模型名 |
| `PERSONA` | 内置默认 | 角色设定，直接影响说话风格 |
| `REPLY_CHANCE` | `0.9` | 收到消息后回复的概率 |
| `IDLE_HOURS` | `4` | 静默多久后开始主动搭话 |
| `QUIET_HOURS` | `8` | 说晚安后不打扰的时长 |
| `VOICE_ENABLED` | `0` | 是否开启语音回复 |

## 关于本仓库

这是一个**脱敏版本**，用于展示代码结构与实现思路：

- **不包含 `archive/` 模块**——那是从真实聊天记录里离线生成语料、人设和表情库的预处理脚本，涉及私人聊天数据，没有公开
- **不包含 `data/` 目录**——运行时的记忆、日志、人设数据都在本地，不入库
- 代码里的角色称呼已替换为通用占位词
- 图片理解、语音、联网搜索需要单独的 API Key，未配置时对应功能自动跳过

机器人使用的 QQ 协议属于非官方接口，仅限个人学习使用，请注意账号风险。
